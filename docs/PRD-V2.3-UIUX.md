# DreaMoon V2.3「UI/UX 優化」PRD

狀態：Draft / 可進入 V2.3.0 開發  
版本：V2.3  
日期：2026-08-05  
產品核心：以編輯內文為主，設定集維持現有入口，不納入本版功能調整。

## 1. 本版決策

### 1.1 內容層級

小說的標準層級固定為：

> 書籍 → 卷 → 節 → 幕

- 「卷」是大型內容分組。
- 「節」是目錄中的實際編輯單位，也是字數、排序、匯出與導覽的主要單位。
- 「幕」是正文內的文字標題，不是獨立資料節點，不計入節次、不出現在左側目錄。
- 幕應沿用目前富文本編輯器的標題段落能力，並在視覺上與一般正文清楚區分。

### 1.2 產品範圍

V2.3 只改善「在編輯區內寫作」的 UI/UX。設定集不提升為專案一級導覽，也不納入本版功能規劃。

設定集在本版只維持現有入口與功能，不進行設定內容或功能面的調整。後續若需要，才另外規劃設定集專案。

## 2. 問題與目標

### 2.1 目前問題

1. 新建書籍後只有「第一卷」，沒有可直接寫作的第一節。
2. 書籍總覽中的新增節入口不夠明顯，空目錄缺乏下一步引導。
3. 「節／章節／第 X 節」命名不一致。
4. 編輯器工具列的匯出功能過於突出，寫作相關操作層級不夠清楚。
5. 編輯區缺少儲存狀態、上下節切換與更清楚的目前位置資訊。
6. 設定集目前分類不完整，未完成入口會讓使用者感覺功能中斷。
7. 書櫃無書籍時缺少明確空狀態與開始行動。

### 2.2 V2.3 目標

- 使用者建立書籍後，30 秒內可以輸入第一段正文。
- 使用者能明確理解「卷、節、幕」的差異。
- 編輯器的主要注意力集中在正文，不被低頻功能干擾。
- 使用者不用離開編輯器，就能維持目前的寫作流程。
- 所有新增、切換、儲存與刪除操作都具備清楚回饋。

## 3. 版本拆分

### V2.3.0：寫作流程與編輯器基礎優化

本版必做，目標是先讓「建立 → 開始寫 → 持續寫」順暢。

#### A. 新書啟動流程

- 新建書籍時自動建立：`第一卷`、`第一節`。
- 建立完成後直接進入第一節編輯器。
- 自動聚焦節標題；使用者按 Tab 或點擊正文即可開始輸入。
- 初次建立時顯示一次性提示：「內容會自動儲存」。
- 若使用者從書籍總覽進入，空卷中提供明確的「新增第一節」主按鈕。

驗收條件：新建書籍後不需要返回總覽或尋找隱藏按鈕即可輸入正文。

#### B. 統一內容命名

- UI 全面使用「卷」「節」「幕」。
- `Section` 在 UI 顯示為「節」，不再顯示「章節」或「第 X 章」。
- 編輯器標題顯示為「第 X 節｜節標題」。
- 新增操作統一為「新增卷」「新增節」。
- 正文標題工具統一為「幕標題」。
- 幕標題只存在於正文富文本，不加入左側目錄、不計入節次。

驗收條件：書籍總覽、編輯器側欄、空狀態、右鍵選單與提示文字沒有混用詞彙。

#### C. 編輯器寫作優先

- 工具列第一層只保留：目錄、設定集、上一節、下一節。
- TXT、EPUB 匯出移至「更多」選單或檔案選單。
- 顯示目前儲存狀態：`已儲存`、`儲存中…`、`儲存失敗`。
- 底部狀態列顯示：字數、目前節次、目前卷名。
- 上一節／下一節在沒有相鄰節時 disabled，並提供 tooltip。
- 切換節時若正文尚未完成 debounce 儲存，先完成當前內容寫入。
- 正文編輯區維持最大可讀寬度，避免三欄同時開啟時文字過窄。

驗收條件：使用者在編輯器內可以完成連續寫作、切換節、查看設定，不需要回到總覽。

#### D. 空狀態與操作可發現性

- 書櫃無書時顯示「建立第一本小說」主按鈕。
- 卷無節時顯示「這一卷還沒有節」與「新增第一節」。
- 編輯器無選取節時顯示「從目錄選擇節，或新增一節開始寫作」。
- 卷列的新增節按鈕保留，但提高點擊區域與 hover 狀態。
- 「新增節」建立後立即選取並進入編輯狀態。
- 刪除節／卷後提供短時間 Undo；Undo 期間不需要重新尋找原位置。

#### E. 設定集範圍鎖定

- 保留目前設定集右側 inspector 的入口與既有功能。
- V2.3.0 不修改設定集分類、欄位、列表、詳細頁、時間軸或關係圖。
- 不因 UI/UX 優化而新增設定項目、刪除設定項目或改變既有資料。

驗收條件：V2.3.0 的編輯器優化不破壞目前設定集功能，且設定集不是本版開發主軸。

### V2.3.1：編輯器導覽與視覺層級優化

本版仍然只處理 UI/UX，不新增或修改設定集功能。

- 優化左側卷／節目錄的縮排、選取、收合與拖曳回饋。
- 優化正文標題、幕標題與一般正文的視覺層級。
- 增加目前卷、目前節與儲存狀態的清楚提示。
- 優化上一節／下一節、返回目錄等編輯流程操作。
- 調整工具列按鈕分組，降低匯出等低頻操作的視覺干擾。
- 優化深色模式的文字對比、分隔線與選取色。
- 改善書櫃卡片、空狀態與書籍總覽的視覺一致性。

驗收條件：使用者能快速理解目前位置、目前狀態與下一個可操作項目，且正文仍是畫面焦點。

### V2.3.2：寫作效率與可及性優化

本版仍然只處理 UI/UX，不新增設定集分類或設定集功能。

- Command palette 與快捷鍵說明面板。
- 最近使用的節與快速跳轉。
- 節次批次調整與大綱重排的操作體驗。
- 寫作統計、每日目標與進度回饋的視覺化。
- 完整 Undo／Trash 操作流程與回饋。
- 鍵盤導覽、焦點狀態與 VoiceOver 可及性改善。
- 視窗縮放、窄欄與不同顯示比例下的響應式排版。

## 4. 不在 V2.3.0 範圍內

- 不建立獨立的世界觀首頁。
- 不重新設計資料模型為完整遊戲引擎。
- 不加入地圖、任務系統、技能樹或資產管理器。
- 不將幕做成獨立的 SwiftData model。
- V2.3 全系列不處理設定集分類、欄位與功能完善；這些內容另立版本規劃。
- 不改變現有 TXT／EPUB 匯出格式，除非命名統一造成必要調整。

## 5. 建議介面結構

```text
書櫃
└── 書籍總覽
    └── 卷／節目錄
        └── 編輯器
            ├── 左側：卷／節目錄
            ├── 中間：節標題＋正文
            └── 右側：現有設定集入口（不改功能）
```

正文內的幕只在中間編輯區呈現：

```text
第 1 節｜夜行

幕標題：雨夜
正文……

幕標題：來客
正文……
```

## 6. 成功指標

- 新建書籍後首次輸入正文的操作步驟 ≤ 2 步。
- 使用者不返回總覽即可新增並切換節。
- 編輯器主要操作中，正文相關操作占工具列可見操作的優先層級。
- 100% 的新增節入口使用「節」命名。
- 設定集入口維持可用，且不影響正文編輯流程。
- 測試使用者能正確說明「卷、節、幕」三者差異。

## 7. 建議開發順序

1. 先完成資料與啟動流程：新書自動建立第一節、直接進入編輯器。
2. 統一 UI 文案與 `幕標題` 顯示規則。
3. 補齊書櫃、卷、編輯器的空狀態。
4. 調整編輯器工具列、儲存狀態與上下節切換。
5. 完成 Undo、細節視覺與可及性驗收。
