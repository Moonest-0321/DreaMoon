# 文件與實作一致性檢查

> 檢查日期：2026-09-01
>
> 範圍：`docs/*.md` 與目前 `Sailune/*.swift` 的公開 UI、資料模型及匯出流程

## 已確認一致

- 書籍以卷／節組織，編輯器提供正文、節標題、上一節／下一節與自動儲存。
- 角色資料包含別名、正文引用、組織、能力、物品、關係與歷史資料。
- 物品定義與物品副本是兩層資料；副本可獨立記錄持有人、等級選擇與歷史。
- 時間軸、紀元、時間釘子與事件的基本資料關係和規格描述一致。
- 故事標籤使用文字錨點與原始位置，且編輯器會以顏色提示。
- TXT／EPUB 匯出依卷節排序，編輯器幕標題會轉換為匯出格式的標題。
- 角色或物品刪除時，正文文字保留的描述與目前介面提示一致。
- V4.2 故事背景、故事線、階段與大綱項目均屬指定書籍，使用穩定 UUID 連結獨立 store。
- V4.2 敘事大綱與時間軸讀寫同一筆 `OutlineItem`，符合「只維護一次」要求；從正文建立時另以至多一筆 `OutlineItemAnchor` 保存來源，不建立第二份大綱內容。
- V4.2 時間軸同時分欄呈現各故事線；同一本書只允許一條主線，主線以階段分段。
- 故事規劃刪除僅影響獨立 store：項目→anchor、故事線→階段／項目／anchors、伏筆／修改→標籤；正文與每節註記不受影響。
- V4.3 階段刪除會一併刪除所屬項目與來源 anchor，並立即刷新對應紅色正文標記；正文文字仍保留。有效正文來源的大綱項目優先依卷／節及文字位置排序，手動／失效來源保留在後方。
- V4.3.1 以獨立 V4 中繼資料保存階段幕／節次起點與手動項目安置，不回寫 V3 模型。正文來源項目才可顯示「已完成」；刪除手動掛點時，依附項目回到待安置並保留內容。
- V2 結構標籤（主軸／支線／計劃加入）在 V3 升級時轉為同 UUID 的大綱項目與錨點，成功後移除舊標籤；伏筆／修改與每節註記不變。主 store 的舊時間軸資料不刪除也不自動轉換。

## 需要留意的邏輯或文件問題

### P1：匯出目的地是實作固定值

- 實作：`ExportManager.swift` 將檔案固定寫入 `/Users/hsuchengyu/Downloads`。
- 影響：換使用者或換電腦時可能無法寫入；文件目前把它描述為既有行為，但尚未形成產品決策。
- 建議：列為待修正功能，改由系統儲存面板讓使用者選擇目的地；在修正前不要承諾跨環境可用。

### P1：刪除流程宣稱不可復原，但復原能力未統一

- 卷／節與部分編輯流程存在「復原」入口，但角色、物品與副本刪除介面明確提示不可復原。
- 影響：使用者對「復原」的期待不一致。
- 建議：在總體資料安全規格中明確區分「編輯撤銷」與「資料刪除復原」，並決定是否提供刪除後復原機制。

### P1：角色名稱同步的自動範圍需明確

- 實作同時支援已連結名稱同步與未連結舊名稱候選替換。
- 影響：若文件只寫「名稱同步」，容易誤解為所有相同文字都會自動替換。
- 建議：保留目前文件的「選擇性套用」表述，並將歧義、同名與別名規則納入正式驗收測試。

### P2：版本號與資料 schema 版本不是同一概念

- Git 提交有 V4.0.1 等產品版本標籤；程式另有 V1、V2、V3、V5 等 SwiftData schema／遷移版本。
- 影響：若混用「版本」一詞，可能誤把資料遷移版本當成產品版本。
- 建議：文件中固定使用「產品版本」與「資料 schema 版本」兩個名稱。

### P2：部分功能仍只有程式事實，缺少產品意圖

- 故事標籤、事件入口、物品等級、時間軸多線並行及匯出設定仍有待確認項目。
- 這不是目前實作錯誤，但在決策前不應把它們寫成不可變規格。

### P2：V4.2 與舊版時間定位仍有相容層

- V4.2 頂層時間軸已改用共用大綱項目，正文右鍵不再建立舊版時間釘子。
- `Timeline`、`Node`、`Event` 與角色／設定歷史的舊時間定位仍保留，以免刪除或錯誤轉換既有資料。
- 在 `OutlineItem` 與各設定歷史的正式關聯定案前，不把舊時間定位自動嫁接到新大綱；相關畫面用語與最終退場方式仍待後續相容性設計。

### P2：V4.2 刪除與復原規則尚未定案

- 第一版沒有提供故事線、主線階段或大綱項目的刪除入口，避免先決定跨 store 清理與復原行為。
- 正式加入刪除前，需一併定義子項目處理、書籍刪除清理、多 store 失敗恢復與驗收測試。

## 本次檢查結論

V4.2 第一版的共用資料、手動狀態、排序、舊資料保留與 schema 遷移和 PRD 一致。仍未定案的 V4.2 刪除／復原、舊時間定位退場與跨模組嫁接已明確保留為後續項目，沒有被改寫成既定行為；既有 P1 項目仍應優先進入後續工作清單。
