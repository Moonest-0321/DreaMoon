## V4.4.6 需求與決策

### 工作單元

- 目標：將寬版世界時間軸改為等距節點軸與事件卡片，使作者能同時安排尚未寫入正文的事件，並辨識已寫入事件及其正文位置。
- 完成條件：本節需求、範圍、非目標、資料語意與驗收條件獲使用者確認後，才進入 UI 提案；本階段不修改功能程式或正式規格。
- 相關範圍：寬版世界時間軸、Node／Event 資料與事件建立／綁定流程、既有日期投影及必要遷移。
- 非目標：不修改敘事大綱；不恢復右側窄欄的管理功能；不重新建立時間序與版面座標的比例關係。

### 現況與差異

- 寬版時間軸目前是「紀元 → 日期 → 事件標題」垂直摺疊清單，不是手稿中的水平軸與卡片。
- 日期投影目前會依整份資料連續省略重複年／月，並依真實日期序位排序；尚無「每一視覺行重新補齊日期」或 viewport 首節點規則。
- Node 已有紀元、年／月／日、時間軸及可選節次；Event 只有標題、詳情、顯示狀態、排序、Node、可選節次與角色。
- Event 尚無明確的已寫入狀態、節錄來源、節錄文字、附屬圖示或與敘事大綱項目的正式關聯。現有 `detail` 不能在未確認前直接等同本版節錄。
- 現行 Node 仍按日期序位排序。Rule 7 若只解除排版比例並不衝突；若允許作者把較晚日期排在較早日期之前，便需要獨立的版面排序資料。

### 已指定需求

1. 世界時間軸使用離散等距節點；相鄰節點固定一格，不按實際相隔年月拉伸距離。
2. 日期採相對簡記：一組顯示序列的第一個節點顯示完整最大日期層級，後續同年／月節點依序省略重複層級。
3. 暫時關閉實際時間前後與時間軸版面位置的強關聯約束；其確切資料語意列於待確認事項。
4. 事件卡片分為「已寫入」與「未寫入（預排／大綱）」：已寫入使用實線框，未寫入使用虛線框。
5. 卡片標題為自訂欄位；空白新卡預設以月／日填入，例如 `3/12`。
6. 未寫入事件由使用者先指定日期建立，之後綁定正文節次時由系統回填卷／節資訊。
7. 已寫入事件由「敘事大綱」選取既有項目帶入，加入世界時間軸時再填對應日期。
8. 卡片節錄可選「內文自動節錄」或「手動自填」，最多 30 字，畫面最多兩行。
9. 卡片右上使用圓形刪除按鈕；刪除沿用明確確認流程，不把它作為角色、分類或狀態標記。

### R 確認採用的細節

- 標題上限採 10 字，卡片內維持單行並以省略號截斷；輸入介面顯示字數。相較 8 字，10 字較能容納專名，且視覺寬度仍由卡片固定寬度控制。
- 日期補齊採資料驅動，不以自適應換行作為持久規則；每個水平可視序列的第一個可見節點顯示完整日期，其後相對簡記，滾動時標籤變化只屬顯示結果，不回寫資料。
- Rule 7 只解除真實時間跨度與畫面距離的比例關係；節點仍依日期由早至晚排列，不允許同一軸上日期與版面順序相反。
- 「已寫入」以存在有效且屬於本書的正文／敘事來源為判定基礎，不讓外框狀態與實際綁定互相矛盾；細節待確認 OutlineItem 與 Event 的關聯方式後定案。
- 既有 `detail` 保留為事件詳情，節錄另設資料；V4.4.6 先改寬版時間軸，右側窄欄維持 V4.4.5a 唯讀清單。

### 待確認事項

1. 已寫入事件是直接綁定 `OutlineItem`，或同時保存 `OutlineItem` 與 `Section`；這項技術語意不改變已確認的使用流程，留到 I 提案比較刪除與失效來源風險。
2. 自動節錄如何在大綱錨點附近取滿 30 字，以及正文修改後動態重算或保存快照；留到 I 提案依既有錨點能力提出安全方案。

### 初步使用流程

- 預排事件：新增卡片 → 指定紀元與日期 → 預設月／日標題，可改名與手填節錄 → 以虛線卡留在時間軸 → 日後綁定正文／敘事項目後回填卷節並轉為實線。
- 已寫入事件：從敘事大綱挑選項目 → 指定世界日期 → 自動帶入卷節與可用節錄 → 以實線卡加入時間軸。
- 閱讀時間軸：節點固定等距排列；日期依選定的資料驅動規則簡記；卡片外框直接表達是否已有有效正文來源。

### 初步驗收條件

- 不同真實時間跨度的相鄰節點在畫面上使用相同節距，且不因日期跨度產生比例空白。
- 日期標籤在紀元／年／月邊界及所選補齊基準下正確顯示，不會因視窗換行把不穩定狀態寫回資料。
- 已／未寫入事件分別穩定呈現實線／虛線；來源失效時有明確降級行為，不誤示為已寫入。
- 新建事件標題有日期預設值並遵守最終字數上限；長標題在卡片內不破壞尺寸。
- 預排事件可先只有日期，綁定後正確顯示卷／節；由敘事大綱加入的事件可指定日期並保留回正文能力。
- 節錄來源可切換，30 字限制與兩行顯示一致；正文修改、來源失效及空內容行為明確。
- 既有 Timeline／Era／Node／Event、主副軸、角色關聯與正文資料不遺失；遷移後可正常重開。
- 右側窄欄與敘事大綱維持既有行為，除非後續 R／U 明確擴張範圍。

### V4.4.6 UI 提案（U，待確認）

#### 資訊架構

1. 頂部第一列保留「主／副軸」選擇及目前軸名稱。
2. 第二列保留時間釘子、紀元、副軸、改元與日期粒度等管理操作，不塞入事件卡片內。
3. 下方改為可水平捲動的等距時間軸；每個節點是一個固定寬度 slot，日期在軸線上方，事件卡在軸線下方。
4. 同一日期有多張卡時在同一 slot 垂直堆疊，不新增重複日期節點；卡片堆疊區由整體垂直捲動畫面承接。

#### 主要畫面線框

```text
時間軸　當前：主時間軸                 [敘事大綱｜時間軸]
[主軸] [副軸…]   [+ 時間釘子] [紀元管理] [+ 副軸] [改元]   粒度 [年 月 日]

        4年6月18日        7月16日             21日              5年1月3日
             ●──────────────●─────────────────●────────────────●──→
        ┌────────────┐  ┌────────────┐    ┌────────────┐
        │ 夜探皇宮  ⓧ│  ┊ 伏擊前哨  ⓧ┊    │ 城門失守  ⓧ│
        │ 第一卷・三節│  ┊ 尚未綁定   ┊    │ 第二卷・一節│
        │ 月下潛入…… │  ┊ 手動節錄…… ┊    │ 守軍撤退…… │
        └────────────┘  └────────────┘    └────────────┘
           已寫入           未寫入              已寫入
```

- `ⓧ` 代表右上圓形刪除按鈕；預設低調顯示，滑入卡片或鍵盤聚焦時提高對比。
- 已寫入卡片為實線；未寫入卡片為虛線。狀態名稱可放入輔助提示，不再額外佔一行。
- 卷／節使用次要文字。未寫入且尚未綁定時顯示「尚未綁定」，綁定後由系統回填。
- 節錄固定最多兩行；標題在資料上最多 10 字，卡片過窄時仍可視覺省略，hover help／輔助標籤提供完整文字。

#### 建立流程

- `+ 時間釘子` 改為打開建立選單：`新增預排事件`、`從敘事大綱加入`、`只新增日期節點`。既有只建立 Node 的能力不消失。
- 新增預排事件：先選紀元與日期；標題自動帶月／日；可立即改標題、選手動節錄或暫留空白。完成後出現虛線卡。
- 從敘事大綱加入：先在可搜尋清單挑選項目，畫面顯示其卷／節與節錄預覽，再指定紀元與日期；完成後出現實線卡。
- 點擊卡片本體開啟事件詳情；已寫入卡片另提供「回到正文」，未寫入卡片提供「綁定敘事大綱」。

#### 日期與捲動

- slot 固定等距，真實日期跨度只影響標籤與排序，不影響距離。
- 水平捲動後，viewport 第一個可見節點動態顯示完整可用日期；後續同年／月節點省略重複層級。跨紀元時強制重新顯示紀元與完整日期。
- 視窗變窄只減少同時可見 slot 數，不產生換行軸；因此不需要以不穩定的「每行第一個」保存規則。

#### 刪除與空白狀態

- 點擊卡片右上刪除按鈕後顯示確認：刪除事件卡不刪正文、敘事項目或日期節點；若同日已無事件，Node 是否保留沿用既有獨立時間釘子語意。
- 刪除日期節點仍由管理操作執行，並清楚提示會連帶刪除該節點事件；不與卡片刪除混用。
- 完全空白時顯示兩個主要入口：「新增預排事件」與「從敘事大綱加入」，另以次要入口保留「只新增日期節點」。

#### U 非目標

- 本輪不改右側唯讀時間標題清單、不改敘事大綱畫布、不加入拖曳改日期，也不讓使用者以拖曳打亂日期先後。

### V4.4.6 實作與測試計畫（I，待確認）

#### 資料設計

1. 不在主 store 的 `Event` 上建立指向 `OutlineItem` 的 SwiftData relationship；兩者位於不同 store，依既有架構以穩定 UUID 連結。
2. 在故事規劃 store 新增 `TimelineEventCardMetadata`：穩定 `id`、唯一 `eventID`、`bookID`、可選 `outlineItemID`、節錄模式 raw value、手動節錄及更新時間。新增 StoryPlanning schema V6，V5→V6 採 lightweight migration；歷史 schema 快照保持不變。
3. `Event.title`、`detail`、`node`、`section`、角色與顯示狀態仍保存在主 store。標題 10 字是本版輸入限制，不截斷既有超長標題資料；舊資料只在卡片視覺省略，作者編輯後才套用新限制。
4. 新增預排事件時建立 Event 與 metadata，但 `outlineItemID`／`section` 為空；從敘事大綱加入或後續綁定時保存 `outlineItemID`，並由有效 `OutlineItemAnchor.sectionID` 回填 `Event.section`。
5. 卡片「已寫入」判定：metadata 可解析到同書 OutlineItem，且其 anchor 可解析到同書 Section。失效時卡片降為虛線並顯示「來源失效」；不自動刪 Event、metadata 或正文。
6. 為相容既有資料，沒有 metadata 但已有同書有效 `Event.section` 的舊事件仍以實線顯示並可回該節，標記為「舊事件」；作者日後可選擇綁定敘事大綱。沒有有效 section 的舊事件顯示為未寫入。
7. 自動節錄不保存正文副本：以 OutlineItemAnchor 重新解析目前正文位置，從該位置起擷取最多 30 個使用者可見字元，合併換行／多餘空白；解析失敗時退回 anchorText，再失敗則顯示空白。手動模式只保存最多 30 字的 `manualExcerpt`。
8. 刪除事件卡只刪 Event 與對應 metadata，不刪 Node、OutlineItem、anchor、Section 或正文。刪除 Node／Timeline 所造成的 Event cascade 後，清理 metadata 孤兒；清理可重複執行。

#### 邏輯與元件拆分

1. 新增純資料投影，例如 `TimelineCardProjection`，負責日期排序、固定 slot、同日事件順序、相對日期標籤、已寫入判定、卷節文字及節錄輸出；View 不直接拼接跨 store 規則。
2. 將 viewport 第一個可見 slot index 作為短期 UI state 傳給標籤投影；只改顯示文字，不修改 Node 或排序。跨紀元及日期粒度切換會重設完整標籤基準。
3. 寬版 `TimelinePanelView` 保留現有軸、紀元、改元、粒度與 Node 管理，替換下方垂直 `TimelineEraGroup` 閱讀區為水平 slot 畫布；窄版及右側唯讀導覽沿用既有元件／投影。
4. 新增共用事件卡 View：固定寬度、實／虛線、標題、卷節、兩行節錄、右上圓形刪除按鈕、完整 accessibility label 與鍵盤 focus。刪除使用既有風格的確認對話框。
5. 新增建立／編輯 sheet，承接三個入口：預排事件、從敘事大綱加入、只新增日期節點。表單驗證紀元、年月日、10 字標題、30 字節錄及來源有效性；保存失敗保留輸入供重試。
6. 點擊卡片開詳情；已寫入卡片可回正文，未寫入卡片可綁定大綱。綁定與解除綁定透過專用協調服務依序保存兩個 store，錯誤需顯示且不得假裝完成。

#### 跨 store 一致性與失敗策略

- 建立／綁定採「先保存主 store Event，再保存 metadata」；第二步失敗時保留 Event，回報未完成並允許重試，不刪除使用者已輸入的事件。
- 卡片刪除先保存主 store 的 Event 刪除，再清理 metadata；若清理失敗，孤立 metadata 不顯示，下一次載入以冪等修復清除。
- 綁定時若 OutlineItem 或 anchor 在保存前失效，中止 metadata 更新並保留原 Event。敘事項目日後被刪除時不跨 store 強制刪 Event，只降級為未寫入／來源失效。
- 不自動替所有舊 Event 建 metadata，也不猜測它對應哪一筆 OutlineItem；避免同節多項目時錯綁。

#### 預定修改範圍

- `BookOutline.swift`／`StoryTag.swift`：StoryPlanning schema V6、metadata 模型、Store 查詢與冪等孤兒清理。
- `TimelineViews.swift`：寬版水平畫布、卡片、建立／編輯／刪除流程與 viewport 標籤狀態；保留窄版及右欄行為。
- 視需要新增獨立投影／協調檔，避免把跨 store 邏輯塞進 View。
- 現有時間軸及故事規劃測試：新增投影、關聯、節錄、遷移與刪除回歸。
- 完成後更新 `spec-timeline.md`、`data-model.md`、`backup-and-migration.md`、`consistency-audit.md`、`project-status.md`、工作單與交接。

#### 測試計畫

- 投影：跨紀元、年／月／日邊界、viewport 起點、不同真實跨度仍等距、同日多事件穩定排序及粒度切換。
- 卡片狀態：新預排、有效大綱來源、失效 anchor、跨書 UUID、既有 section-only Event、無來源舊 Event及解除綁定。
- 節錄：中文與 emoji 的 30 字限制、UTF-16 錨點解析、換行壓縮、正文更新後動態結果、重複 anchorText 與解析失敗 fallback。
- 建立／保存：三種入口、預設月／日標題、10 字限制、空白與錯誤輸入、同日新增、跨 store 第二步失敗與重試不重複。
- 刪除：刪卡保留 Node／OutlineItem／Section／正文；刪 Node／Timeline cascade 後清除 metadata；重複清理安全。
- 遷移：代表性 StoryPlanning V5 store 升至 V6，UUID／數量／既有大綱關聯不變；主 V5 store 不需 schema 變更並可重開。
- 回歸：主／副軸、紀元、改元、粒度、可見性、角色關聯、右欄唯讀清單、敘事大綱與正文跳轉均保持。
- 驗證：完整 macOS 測試、Debug、無簽章 Release、`git diff --check`；以隔離資料實測空白、預排、已寫入、同日多卡、水平捲動補齊、刪卡／刪 Node 及重開保存。

#### 主要風險與控制

- 兩個 store 沒有共同交易：以可重試協調流程、孤兒清理及失敗測試控制，不宣稱原子寫入。
- viewport 動態標籤容易造成捲動時跳動：slot 尺寸不因文字長度變化，標籤固定寬度並只換文字。
- 自動節錄可能遇到重複文字：沿用既有「離原 offset 最近」規則，不在本版擴張上下文錨點 schema。
- 舊 Event 無法可靠猜到 OutlineItem：保留 section-only 相容狀態，不自動建立錯誤關聯。

## V4.4.5b 問題診斷

### 使用者回報

- 大綱標題的正文跳轉無法每次精確到達預期文字位置。

### 已確認原因

1. 跨節跳轉時，`EditorBridge` 先保存目標 section 與選取 range；`RichEditorView.updateNSView` 切到新節後卻會在正文實際套用前清除 pending selection 並呼叫 `select`。
2. 長文或一般非同步載入完成後，`Coordinator.apply(..., resetSelection: true)` 再次重設游標，覆蓋先前選取。因此相同節通常可精確跳轉，跨節則依更新時序偶發只到節次或錯誤位置。
3. 既有測試只涵蓋 `ProseAnchorResolver` 的 offset 計算，沒有覆蓋跨節非同步載入與 pending selection 的消費順序。

### 次要限制

- 同一節若有多段完全相同的 `anchorText`，目前依舊 `anchorOffset` 選最近候選；大量改稿使相對位置改變時仍可能選到另一段。此為錨點消歧能力限制，與本次確定的載入競態分開處理。

### 建議修正範圍

- 跨節時將 pending selection 保留到新節正文 `apply` 完成後，再執行選取、捲動與 focus；只有成功套用目標 section 才清除請求。
- 同節跳轉維持立即選取，不增加延遲。
- 加入可測試的 pending-selection 消費規則與跨節回歸測試；不修改 UI、錨點 schema 或既有資料。
- 本輪先修正確定的載入競態；重複文字的進階消歧若仍有案例，再另行設計上下文錨點。

### 關卡

- 此為既有行為的明確可靠性修正，沒有 UI 或資料模型變更；U 記為 `not_applicable`。
- 使用者於 2026-09-09 以「同意」授權修正與測試；視為 R／I 已批准。

### 實作與驗證結果

- `EditorBridge` 新增按目標 section 消費 pending selection 的單一入口；非目標節無法提前清除請求。
- `RichEditorView` 在初次建立或跨節套用正文時記錄正在載入的 section；載入完成、文字已套用後才消費選取、捲動並聚焦。內容已就緒的同節跳轉仍立即執行。
- 補上兩項回歸測試：來源節不得消費跨節請求、目標節仍在載入時不得立即選取。完整 macOS 測試由 56 增為 58 項並全部通過。

- 未修改錨點 schema、正文、故事資料或 UI。重複 `anchorText` 在大量改稿後的消歧限制仍保留為獨立後續議題。

### 問題與目標

- 已於 2026-09-04 實際檢視 app 的「大綱／敘事大綱／主線」畫面：它位於右側窄欄，階段標題列只有名稱、收合與刪除；展開後的項目卡同時堆疊標題、內容、來源回跳、狀態、卷／節、移至階段、儲存與刪除。現況已成為本輪 UI 設計基線。
- 目前階段以其所屬最早正文項目隱性推定起點；作者無法一眼確認或穩定控制「這一幕從哪裡開始」。
- 目前狀態選單中的「已發生」可由手動項目任意選取，會混淆「正文已完成」與「作者預定／構想」。
- 手動項目沒有正文錨點，現行只可靠 `sortOrder` 作隱藏後備，作者不能以故事語意控制它應顯示在哪裡。
- 現有右欄的單筆項目編輯列資訊與操作過密；作者難以在掃讀故事時辨識來源、完成情況與下一步。

### 提案規則

1. 每個主線階段均有明確的開始定位，統一參照既有書籍結構的兩層位置「幕／節次」，不再由某筆項目反推。有效來源顯示目前名稱；原定位的幕或節被刪除時，保留最後可讀的名稱與識別，顯示「來源已刪除」，不得自動改指向其他位置。
2. 「已完成」是正文來源的事實標記：只有從正文選取文字建立的項目可取得；手動新增項目只可為背景、草稿或預定。既有手動「已發生」資料必須保留，並以「需要補正文來源或調整狀態」提示作者，不能靜默改寫。
3. 手動項目以「安置位置」取代排序數字：建立後先顯示在所屬階段的「待安置」區；作者可選擇放在幕首、幕末，或接在該幕某一筆項目之後。同一掛點的多筆手動項目可用清楚的上／下移動調整先後，不使用裸露的數字排序。
4. 排序規則以作者可預測的方式組合：階段先依其開始的幕／節次排序；正文項目依正文位置排序；手動項目依其安置位置插入，沒有安置時固定留在「待安置」區。安置目標被刪除時，項目回到待安置並顯示原因，不隨意改放他處。
5. 使用清楚的提示區分「正文定位」、「尚未寫入正文」、「來源已刪除」、「待安置」與「需要調整狀態」；每一種提示都提供下一個可做操作。
6. 大綱介面以可掃讀的階段卡片為主：標題列顯示階段名稱與開始定位；項目預設只顯示標題、事實／規劃狀態與來源／安置資訊，點選才展開內容與次要操作。階段／項目的危險刪除仍保留明確確認。

### V4.3.1 UI 提案（U）

#### 保留既有結構

- 保留現有三欄工作區、右欄的「故事背景／敘事大綱／時間軸」頁籤，以及故事線選擇器；本輪不另建全螢幕大綱頁。
- 保留主線階段的垂直排列與收合；「未分階段」只承接舊資料或未能歸屬的資料，預設收合，不再是新手動項目的預設落點。

#### 階段卡片

- 每張階段卡標題列分兩行：第一行是收合、階段名稱與更多操作；第二行是「開始於　幕名 · 第 N 節｜節次名稱」。來源已刪除時改為「原定位　…（來源已刪除）」，以醒目但非破壞性警示呈現。
- 新增或重新定位階段時，從更多操作開啟小型 sheet，依序選擇「幕」與「節次」；兩者皆為必填。尚未有可用節次時，說明需先在左欄建立正文結構，不能建立沒有定位的階段。
- 階段更多操作只保留「重新定位」、「重新命名」與「刪除階段」。刪除確認明示將刪除多少項目與正文標記、正文文字保留。

#### 項目列與編輯

- 項目預設為一行摘要：狀態圓點、標題、第二行的正文來源或安置資訊，及右側小型狀態標籤。作者可掃讀而不需展開全部內容。
- 正文來源項目顯示綠色「已完成」標籤與「正文：幕／節次」；其完成狀態不可改，展開後可用「回到正文」跳轉。
- 手動項目顯示背景、草稿或預定標籤；展開後才顯示內容、所在階段、安置位置、儲存與刪除。維持既有明確儲存策略，但把儲存按鈕移至展開的編輯區，避免每一列都堆滿按鈕。
- 舊手動「已完成」項目以黃色「需要調整狀態」提示取代可編輯的完成標籤；展開後說明「請從正文建立，或改為草稿／預定」，由作者主動決定。

#### 手動項目的安置

- 每張階段卡內保留「＋ 新增規劃項目」，新增後直接展開為手動項目，初始狀態為草稿、位置為「待安置」。
- 「安置…」只在手動項目的展開區提供，選單依序為「放在本幕開頭」、「接在某一項目後」、「放在本幕結尾」。選擇掛點後，項目立即顯示在該位置；同一掛點的手動項目提供上／下移動。
- 待安置項目聚集在該階段最下方，使用虛線區與「安置…」按鈕提示；掛點項目被刪除時，回到這裡並顯示「原掛點已刪除」。

#### 空白與例外

- 沒有階段時，顯示單一「建立第一幕」按鈕與「請先選擇開始幕與節次」說明。
- 有階段但沒有項目時，展開後只顯示「尚未安排項目」與新增規劃項目。
- 原定位被刪除的階段及舊手動已完成項目不阻礙閱讀或寫作；只在對應卡片顯示可行的修正操作。

### V4.3.1 實作與測試計畫（I）

#### 資料、相容性與遷移

1. 新增 `StoryPlanningSchemaV4`，保留 V1～V3 快照完全不動；V4 只加入兩個獨立中繼模型，不改寫既有 `OutlineStage` 或 `OutlineItem` 的已發布欄位。
   - `OutlineStageStartAnchor`：每階段至多一筆，保存 `stageID`、`bookID`、幕（既有 `Volume`）ID、節次（既有 `Section`）ID，以及當時的幕／節名稱快照。
   - `OutlineItemPlacement`：每手動項目至多一筆，保存 `outlineItemID`、安置類型（待安置／幕首／接在項目後／幕末）、可選掛點項目 ID、原掛點標題快照與同掛點內的穩定順序。
2. 將 V3→V4 設為 lightweight migration；開啟後只為新資料建立中繼模型，不從最早正文項目反推既有階段起點。既有階段顯示「需要設定開始位置」，由作者主動選擇；既有手動項目顯示「待安置」。這避免將舊資料猜成作者意圖。
3. `OutlineStageStartAnchor` 透過 UUID 參照主 store，顯示時由 `BookStructure` 解析目前幕／節次名稱；解析失敗則使用快照並標示「來源已刪除」。它不建立跨 store SwiftData relationship，也不因刪除正文結構而刪除階段。
4. 保留 `OutlineItemStatus.occurred` 現有持久化 raw value，僅將 UI 名稱改為「已完成」，避免既有字串資料失效。所有手動建立／更新入口改由 `StoryPlanningStore` 驗證，不允許沒有 `OutlineItemAnchor` 的項目設為 `.occurred`；舊手動 `.occurred` 資料只標記需處理，直到作者自行改狀態或從正文重建。
5. 不再把 `sortOrder` 視為手動項目的可操作位置。`StoryPlanningStore` 新增安置、重新安置與同掛點上／下移動操作，統一檢查同故事線／同階段、掛點存在與無循環。掛點項目被刪除時，同一交易把依附項目改為「待安置／原掛點已刪除」，保留項目內容。

1. 擴充 `StoryPlanningStore.reload()`、建立／刪除項目、刪除階段與刪除故事線的清理範圍，使中繼資料不會孤立；所有刪除仍不改正文內容。
2. 新增純資料的定位解析器：輸入目前 `Book` 的幕／節次順序，輸出階段定位狀態（有效、待設定、來源已刪除）與顯示文案。View 不直接推算跨 store 資料狀態。
3. 改寫階段排序為「有效開始位置 → 待設定／來源已刪除 → 原有穩定順序」。同一階段內改為「幕首手動項目 → 正文位置項目及其掛接項目 → 幕末手動項目 → 待安置」；同掛點以局部穩定順序排列。
4. 從正文建立主線項目時，以已設定且有效的階段開始位置判斷所屬階段；沒有有效定位的舊階段不參與自動分派，新項目在有可用開始定位時歸入最近且不晚於正文位置的階段，否則進入主線的待處理區並提示作者安置。

## 現況與問題

- 故事背景目前只有一個 `backgroundText` 長文字欄位，沒有任何可選填寫引導。
- 大綱項目以 `sortOrder` 作為無正文來源時的既有後備排序；正文建立的項目雖有 `OutlineItemAnchor`，但錨點的節與文字位置尚未參與排序。
- 主線階段目前以同一故事線內容區內的可選下拉欄位指定；未選階段的項目獨立顯示於共用區域。

## 需求提案（R）

### 1. 故事背景的選填引導

- 保留既有自由長文字區，作為作者可任意記錄的「其他背景」；不要求填寫任何建議欄位。
- 在其上方加入一組可留白的建議區域，候選項目為：世界／時代背景、故事前提、主要衝突、主角目標、核心主題。
- 建議欄位僅協助作者思考，不自動產生、不限制字數、不影響大綱項目或匯出。

### 2. 大綱排序以文本位置優先

- 具 `OutlineItemAnchor` 的項目，優先依正文書籍結構中的卷／節順序，再依該節內錨點位置排序。
- 沒有正文來源的手動項目仍可保留，並排在同一故事線（或階段）中具正文來源項目之後；彼此依既有手動 `sortOrder`、建立時間與 UUID 穩定排序。
- 若錨點指向已不存在的節，不刪除資料；視為無法定位的項目，排在有可用正文位置的項目之後。
- 此提案以「文本內位置」解讀為目前書籍的卷／節顯示順序加上節內 offset；不依文字內容匹配後的動態位置改寫資料。
- 項目編輯列不提供手動輸入排序值；改為唯讀分別顯示正文來源的「卷」與「節」。沒有可用來源、來源已失效或任一名稱未填時，該欄顯示「從缺」。既有 `sortOrder` 不清除，暫作穩定後備排序，待後續另行設計手動排序操作。

### 3. 階段改為獨立欄位

- 僅主線使用階段欄位。每一個既有階段都各自顯示為一個內容區塊，項目直接建立於該階段內，不再於每筆項目的公共編輯區以下拉選單選取階段。
- 手動新增主線項目時，若已有階段，一律歸入排序最後的階段；作者可在項目編輯時移至另一階段。從正文加入主線項目時，每個階段以其中最早的正文來源位置為開始標記，新項目歸入最近且不晚於其文本位置的階段；在所有開始標記之前則歸入第一階段，沒有可用開始標記時才歸入最後階段。
- 未建立任何階段的主線維持一個「未分階段」欄位，不阻礙既有資料；非主線故事線維持單一內容欄位。
- 既有 `stageID == nil` 的主線項目保留在「未分階段」欄位，不會在遷移時自動改寫到最後一個階段。

## 初步驗收條件

- [ ] 故事背景提供已確認的一組選填引導欄位，所有欄位留白時仍可只使用自由文字區。
- [ ] 具有效正文來源的大綱，依卷／節與節內文字位置先後排列；手動項目與無效來源資料仍可見且排序穩定。

- [ ] 既有 V4.2.1 資料、正文、來源錨點、故事線與手動項目均不遺失或被不預期改寫。

## UI 提案（U）

### 故事背景

- 依序顯示五個可折疊、可留白的文字欄位：世界／時代背景、故事前提、主要衝突、主角目標、核心主題。

- 主線顯示為一串垂直欄位：先是「未分階段」（只在含既有未分階段項目或尚無階段時顯示），再依階段排序逐一顯示「階段名稱」與該階段項目。「未分階段」與每個階段皆預設收起，作者點擊標題列後才展開內容。
- 每一階段標題列提供「＋ 新增項目」；在主線工具列新增的項目直接進入最後一個階段。非主線故事線維持既有單一內容欄位。

- 每筆主線項目編輯列的狀態旁加入「移至階段」選單；目前階段顯示為選取值，選擇「未分階段」可移出階段。
- 每筆項目編輯列在狀態旁唯讀分別顯示「卷」與「節」來源；不顯示或允許編輯排序數字。

### 時間軸

- 維持故事線分欄；主線欄內依階段加上小標題分區，不增加第二套項目編輯或排序規則。
- 所有項目仍是同一筆 `OutlineItem`，從敘事大綱或時間軸編輯後同步反映。

### 空白與例外狀態

- 主線沒有階段：僅顯示預設收起的「未分階段」；展開後顯示新增項目按鈕。
- 已有階段但沒有項目：階段預設收起；展開後顯示空白提示與新增按鈕。
- 主線沒有項目但有階段：工具列新增項目直接進入最後一個階段。
- 無正文來源、失效來源、或手動建立項目：不顯示錯誤，置於所屬欄位最下方。
