## V4.4 需求（R，已確認）

### 現況與問題

- V4.3.1 已建立階段定位、正文來源狀態與手動項目安置規則，但大綱仍位於 250～400pt 的右側設定欄；它適合寫作中的快速查看，不適合作為全書規劃的主要工作面。
- 故事背景、敘事大綱與時間軸目前同列於右欄，造成全書規劃、跨故事線比較與項目編排需要在狹窄欄位內反覆展開及垂直捲動。

### 目標與範圍

1. 新增同一書籍視窗內的寬版「大綱工作區」，作為整本書的規劃面；它取代中央文本區，不另開視窗或浮動面板。
2. 工作區只承接「敘事大綱」與「時間軸」，預設進入敘事大綱；沿用 V4.3.1 的資料、排序、安置、狀態及正文來源規則。
3. 大綱工作區不顯示左側正文目錄。選擇「回到正文」時直接切回文本區並定位來源，不使用中繼目錄。
4. 將故事背景移至書籍總覽：書籍資訊依序為基本資訊、封面、簡介、故事背景與統計；背景緊接在簡介下方，預設為可展開摘要卡，展開後使用書籍總覽的完整寬度編輯，資料與既有自由文字相容行為不變。
5. 編輯器頂端工具列移除「寫作／大綱」換頁控制；「大綱」為直接開啟工作區的按鈕，位於右側設定集按鈕與最右側快捷鍵按鈕之間。
6. 右側設定集保留且在大綱工作區預設關閉。本輪不新增右欄「在大綱工作區開啟」入口，工具列大綱按鈕是唯一的新入口。

### 非目標

- 不在本輪加入角色、陣營、物品或其他 V5 設定資料與大綱項目的新關聯。
- 不改寫 StoryPlanning schema V4 或 V4.3.1 的已確認資料規則。
- 不移除文本編輯器既有的左側目錄。

### 驗收條件

- [ ] 作者可由編輯器頂端工具列直接開啟大綱工作區；按鈕順序符合「設定集｜大綱｜快捷鍵」。
- [ ] 大綱工作區以完整中央寬度呈現敘事大綱與時間軸，沒有左側正文目錄，預設顯示敘事大綱。
- [ ] 在大綱任一正文來源項目選擇回到正文後，回到文本區並定位原段落。
- [ ] 書籍總覽在封面與簡介後方顯示故事背景摘要卡；展開後可用完整寬度閱讀與編輯，舊背景資料保持可讀。
- [ ] 不新增右欄前往工作區入口；設定集在大綱工作區預設關閉。
- [ ] V4.3.1 的階段定位、安置、狀態、排序與刪除保護回歸通過。

### V4.4 UI 提案：時間軸（已確認）

- 時間軸使用書籍既有的幕／節次順序作為橫軸，不假設故事內已有年、月、日等絕對時間。
- 每條故事線是一條橫向泳道；項目卡依正文來源位置或既有手動安置規則對齊至對應幕／節次。泳道標籤是比較用列標，不是左側正文目錄。
- 已完成、背景／草稿／預定與來源已刪除維持既有視覺語意；手動待安置、失效來源或無法對應者固定留在時間軸底部的「待安置」，不可偽造一個時間位置。
- 時間軸項目以摘要比較為主；選取後提供回到正文，內容與安置等編輯仍在敘事大綱進行，避免橫向泳道塞入完整表單。

### V4.4 UI 提案（U，已確認）

- 寫作工具列右側順序為「設定集｜大綱｜快捷鍵」；大綱是直接進入獨立工作區的入口，不另設寫作／大綱換頁控制。
- 寫作區保持既有左側正文目錄與中央文本；大綱工作區不顯示左側正文目錄，以完整中央寬度呈現內容。由來源項目選擇回到正文時，切回文本區並定位。
- 工作區包含「敘事大綱」與「時間軸」：前者為垂直階段帶與可展開項目摘要，後者為以幕／節次為橫軸、故事線為泳道的橫向比較圖。
- 書籍總覽順序為基本資訊、封面、簡介、故事背景、統計；故事背景預設摘要卡，展開後才以總覽寬度編輯。
- V4.4 不新增寫作右欄的工作區捷徑；右側設定集在工作區預設關閉。

### V4.4 實作與測試計畫（I，已確認）

#### 前置驗證與導航

1. 先以隔離資料完成 V4.3.1 人工 UI 冒煙：階段定位、來源已刪除、摘要／展開、手動安置與舊手動完成提示。它確認既有資料規則後，才開始搬動呈現層。
2. 將目前以 `BookRoute.opensEditor` 區分的書籍導航改為明確目的地（書籍總覽／文本編輯器／大綱工作區），使工具列的大綱入口可從文本區導航到同一書籍的獨立工作區，而不是在窄欄內切換 View。
3. 從工作區回到文本時保留書籍與來源節次；選取正文來源項目時先提交待存文字，再以既有 `EditorBridge.requestSelect` 切到該節並選取錨點。未帶正文來源的項目不顯示回正文操作。

#### View 與資料投影

1. 新增 `BookPlanningWorkspaceView` 作為無左側正文目錄的寬版容器；它提供「敘事大綱／時間軸」切換、回到文本與故事線操作，右側設定集預設關閉。
2. 將既有 `BookOutlineWorkspaceView` 的可重用故事線、階段、項目摘要與編輯 View 拆出，讓側欄與寬版敘事大綱共用同一組狀態、刪除確認和 store 操作；不建立第二份大綱資料。
3. 新增純資料 `OutlineTimelineLayout`：根據 `BookStructure.orderedSections(in:)`、`orderedStages`、`orderedItems` 與 item placement，輸出幕／節次橫軸、故事線泳道、項目位置與待安置清單。正文錨點依節次／offset 定位；幕首／幕末／掛點手動項目依其現有排序插入；失效來源、無來源且待安置、或無法解析位置者不得猜測座標，固定留在待安置區。
4. 時間軸卡只顯示摘要、狀態與來源／安置；回正文使用既有 callback。完整標題、內容、狀態、安置與破壞性操作維持在敘事大綱，避免泳道上的表單競爭寬度。
5. 修改 `BookOverviewView`／`BookInfoPanel` 的顯示順序為基本資訊、封面、簡介、故事背景、統計。背景摘要卡讀取同一筆 `BookPlanningProfile`，展開後以總覽完整寬度呈現既有五個引導欄位與其他背景；沒有 profile 時保留可建立的空白狀態。
6. `WorkspaceInspectorView` 不新增工作區捷徑；移除其中的故事背景頁籤，避免與書籍總覽重複。其餘既有側欄大綱行為維持，直到另有明確的精簡規格。

#### 資料相容性、文件與風險

1. 不新增或變更 SwiftData schema：背景仍使用 `BookPlanningProfile.backgroundText`，大綱／時間軸仍共用 `OutlineItem`、anchor、stage start anchor 與 placement。
2. 更新故事規劃規格、資料模型、遷移／備份與一致性檢查，記錄背景入口移動、工作區／側欄責任、時間軸投影與「待安置不偽造時間位置」規則。
3. 路由重構須避免 `EditorWorkspaceView` 中 AppKit 文字編輯器在 navigation 轉換時遺失未提交內容；所有離開文本區的入口統一 flush。
4. 時間軸只能表達書籍結構順序，不宣稱為世界內絕對年代；既有舊 `Timeline`／`Event` 相容層不在此輪移除或改寫。

## V4.3.1 需求調整（R，已確認）

> 本節由 2026-09-04 使用者提出；它改變既有 V4.3 的階段定位與項目狀態規則，因此 R／U／I 均須重新確認。下方既有 V4.3 實作與驗證記錄保留作為現況，不表示已符合本節。

### 問題與目標

- 已於 2026-09-04 實際檢視 app 的「大綱／敘事大綱／主線」畫面：它位於右側窄欄，階段標題列只有名稱、收合與刪除；展開後的項目卡同時堆疊標題、內容、來源回跳、狀態、卷／節、移至階段、儲存與刪除。現況已成為本輪 UI 設計基線。
- 目前階段以其所屬最早正文項目隱性推定起點；作者無法一眼確認或穩定控制「這一幕從哪裡開始」。
- 目前狀態選單中的「已發生」可由手動項目任意選取，會混淆「正文已完成」與「作者預定／構想」。
- 手動項目沒有正文錨點，現行只可靠 `sortOrder` 作隱藏後備，作者不能以故事語意控制它應顯示在哪裡。
- 現有右欄的單筆項目編輯列資訊與操作過密；作者難以在掃讀故事時辨識來源、完成情況與下一步。

### 提案規則

1. 每個主線階段均有明確的開始定位，統一參照既有書籍結構的兩層位置「幕／節次」，不再由某筆項目反推。有效來源顯示目前名稱；原定位的幕或節被刪除時，保留最後可讀的名稱與識別，顯示「來源已刪除」，不得自動改指向其他位置。
2. 「已完成」是正文來源的事實標記：只有從正文選取文字建立的項目可取得；手動新增項目只可為背景、草稿或預定。既有手動「已發生」資料必須保留，並以「需要補正文來源或調整狀態」提示作者，不能靜默改寫。
3. 手動項目以「安置位置」取代排序數字：建立後先顯示在所屬階段的「待安置」區；作者可選擇放在幕首、幕末，或接在該幕某一筆項目之後。同一掛點的多筆手動項目可用清楚的上／下移動調整先後，不使用裸露的數字排序。
4. 排序規則以作者可預測的方式組合：階段先依其開始的幕／節次排序；正文項目依正文位置排序；手動項目依其安置位置插入，沒有安置時固定留在「待安置」區。安置目標被刪除時，項目回到待安置並顯示原因，不隨意改放他處。
5. 使用清楚的提示區分「正文定位」、「尚未寫入正文」、「來源已刪除」、「待安置」與「需要調整狀態」；每一種提示都提供下一個可做操作。
6. 大綱介面以可掃讀的階段卡片為主：標題列顯示階段名稱與開始定位；項目預設只顯示標題、事實／規劃狀態與來源／安置資訊，點選才展開內容與次要操作。階段／項目的危險刪除仍保留明確確認。

### 初步驗收條件

- [ ] 使用者可為每個主線階段選擇並看到其「幕／節次」開始定位；來源刪除後仍可辨識原定位並標記已刪除。
- [ ] 手動新增無法選擇「已完成」；正文建立的項目會自動標為「已完成」。

### V4.3.1 UI 提案（U）

#### 保留既有結構

#### 階段卡片

- 每張階段卡標題列分兩行：第一行是收合、階段名稱與更多操作；第二行是「開始於　幕名 · 第 N 節｜節次名稱」。來源已刪除時改為「原定位　…（來源已刪除）」，以醒目但非破壞性警示呈現。

#### 項目列與編輯

- 項目預設為一行摘要：狀態圓點、標題、第二行的正文來源或安置資訊，及右側小型狀態標籤。作者可掃讀而不需展開全部內容。
- 正文來源項目顯示綠色「已完成」標籤與「正文：幕／節次」；其完成狀態不可改，展開後可用「回到正文」跳轉。
- 手動項目顯示背景、草稿或預定標籤；展開後才顯示內容、所在階段、安置位置、儲存與刪除。維持既有明確儲存策略，但把儲存按鈕移至展開的編輯區，避免每一列都堆滿按鈕。
- 舊手動「已完成」項目以黃色「需要調整狀態」提示取代可編輯的完成標籤；展開後說明「請從正文建立，或改為草稿／預定」，由作者主動決定。

#### 手動項目的安置

- 每張階段卡內保留「＋ 新增規劃項目」，新增後直接展開為手動項目，初始狀態為草稿、位置為「待安置」。
- 「安置…」只在手動項目的展開區提供，選單依序為「放在本幕開頭」、「接在某一項目後」、「放在本幕結尾」。選擇掛點後，項目立即顯示在該位置；同一掛點的手動項目提供上／下移動。

- 沒有階段時，顯示單一「建立第一幕」按鈕與「請先選擇開始幕與節次」說明。
- 有階段但沒有項目時，展開後只顯示「尚未安排項目」與新增規劃項目。
- 原定位被刪除的階段及舊手動已完成項目不阻礙閱讀或寫作；只在對應卡片顯示可行的修正操作。

## 需求提案（R）

### 1. 故事背景的選填引導

- 保留既有自由長文字區，作為作者可任意記錄的「其他背景」；不要求填寫任何建議欄位。
- 在其上方加入一組可留白的建議區域，候選項目為：世界／時代背景、故事前提、主要衝突、主角目標、核心主題。
- 建議欄位僅協助作者思考，不自動產生、不限制字數、不影響大綱項目或匯出。

### 2. 大綱排序以文本位置優先

- 具 `OutlineItemAnchor` 的項目，優先依正文書籍結構中的卷／節順序，再依該節內錨點位置排序。
- 沒有正文來源的手動項目仍可保留，並排在同一故事線（或階段）中具正文來源項目之後；彼此依既有手動 `sortOrder`、建立時間與 UUID 穩定排序。
- 若錨點指向已不存在的節，不刪除資料；視為無法定位的項目，排在有可用正文位置的項目之後。
- 此提案以「文本內位置」解讀為目前書籍的卷／節顯示順序加上節內 offset；不依文字內容匹配後的動態位置改寫資料。
- 項目編輯列不提供手動輸入排序值；改為唯讀分別顯示正文來源的「卷」與「節」。沒有可用來源、來源已失效或任一名稱未填時，該欄顯示「從缺」。既有 `sortOrder` 不清除，暫作穩定後備排序，待後續另行設計手動排序操作。

### 3. 階段改為獨立欄位

- 僅主線使用階段欄位。每一個既有階段都各自顯示為一個內容區塊，項目直接建立於該階段內，不再於每筆項目的公共編輯區以下拉選單選取階段。
- 手動新增主線項目時，若已有階段，一律歸入排序最後的階段；作者可在項目編輯時移至另一階段。從正文加入主線項目時，每個階段以其中最早的正文來源位置為開始標記，新項目歸入最近且不晚於其文本位置的階段；在所有開始標記之前則歸入第一階段，沒有可用開始標記時才歸入最後階段。
- 未建立任何階段的主線維持一個「未分階段」欄位，不阻礙既有資料；非主線故事線維持單一內容欄位。
- 既有 `stageID == nil` 的主線項目保留在「未分階段」欄位，不會在遷移時自動改寫到最後一個階段。

### 風險與回復

- 背景引導不升級 schema；舊自由文字僅在使用者儲存時轉為結構值，且完整保留在其他背景。
- 故事規劃 store 不直接讀主 store；排序只接收唯讀節順序與內容快照，不建立跨 store relationship 或交易。
- 正文重複文字會使最近位置推定有歧義；沿用既有最接近原 offset 規則，失效時保留項目並置後。
- 不移除 `sortOrder`，讓手動或失效來源資料仍有可預測順序。
