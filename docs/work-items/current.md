## 使用者目前進度

- 使用者確認 V5 以勢力系統及其他設定集為方向，並新增需求：設定集可以選擇哪些項目留在側邊欄。
- 新書需要有預設顯示項目，也需要有可由作者自行加入的選項；預設項目仍可被移除顯示。
- 使用者決定組織與陣營要整合並分類為同一個上層「勢力」設定集；標籤也納入可自選的設定集項目。
- 使用者追加勢力層級流程：勢力必須先取得一個具體層級，之後才能選擇其直屬上級或下級。
- 使用者再次指出原始需求：每本書預設建立兩個可重新命名的層級，不是空白層級清單。
- 勢力詳情需保留原始草稿中的完整項目：隸屬／被隸屬、高層管理員、其他名單（職稱／人名）、勢力關係、簡介、政治與宗教。
- 層級由每本書自行建立名稱與排序；跨級直屬有效，不要求上下層相鄰。
- 若修改某個勢力的層級會讓既有隸屬不再符合「下級隸屬上級」，系統必須阻止修改，不可自動刪除關係。

## 問題、期待與不可破壞事項

- 問題：目前設定集是固定分頁；角色、能力、物品、標籤固定存在，組織沒有獨立入口，無法依作品類型降低側邊欄複雜度。
- 期待結果：每本書可以獨立管理設定集項目的顯示、隱藏與順序；隱藏只影響導航，不刪除任何設定資料。
- 必須保留：正文寫作不依賴設定集；既有角色、能力、物品、標籤資料不因隱藏而遺失；既有 UUID、跨 store 關聯與投影行為不變。舊組織資料依 V5 決策清除，不作保留。

## 建議的初始分類

以下是 R 已確認的初始分類；側邊欄具體呈現方式仍由 U 階段確認：

### 新書預設顯示

- 角色
- 勢力（包含組織與陣營）
- 物品
- 能力
- 標籤

理由：角色、組織、陣營是社會與勢力骨架；物品與能力是目前已成熟且常用的設定類型。

### 可自選添加

- 地點
- 世界條目／專有名詞
- 其他未來具體模型（待後續需求確認）

標籤納入同一個自選清單；它仍保留寫作／規劃用途，但顯示與隱藏由作者自由控制。

## 範圍

### 必要

- 定義設定集目錄與每個項目的顯示名稱、圖示、排序及可用狀態。
- 為每本書保存目前顯示的設定集項目與顯示順序。
- 新書依預設清單建立配置。
- 作者可從側邊欄移除預設項目，也可從「新增設定」加入可選項目。
- 作者可恢復預設配置，但恢復不刪除任何資料。
- 所有設定資料繼續保留於原本 store；側邊欄配置只負責導航顯示。
- 所有設定集項目在被隱藏時不刪除資料；管理面板可重新顯示。V5 不保留正文右鍵的舊組織入口，也不新增勢力正文連結。
- 「勢力」頁面以單一勢力節點處理組織／陣營整合，不建立組織／陣營子分類。
- 每本書可建立、命名與排序自己的勢力層級；每個勢力在建立上下隸屬前必須有且只有一個層級。
- 新增上級時只列出比目前勢力更高的層級所包含之勢力；新增下級時只列出更低層級的勢力，允許略過中間層級直接隸屬。
- 勢力層級變更若會使任何既有直屬關係失效，阻止變更並指出衝突，不自動移除關係。

### 可選

- 設定項目拖曳排序。
- 每個設定項目的說明與「目前已有幾筆資料」提示。
- 新版本新增設定類型時，以「可新增」顯示，不自動插入已被作者自訂過的書籍。

### 非目標

- 不建立沒有明確用途的泛用 `OtherSetting` 模型。
- 不因隱藏側邊欄項目而刪除、封存或修改其資料。
- 不在本工作同時完成地圖、宗教、經濟、語言或科技樹等專門設定模型。
- 不在 R 階段修改正式 UI、SwiftData schema 或功能程式。

- 是否適用：是；原設定集與單一勢力入口、以下層級管理與先後順序均已確認。
- 入口：設定集標題列新增「管理設定集」按鈕；也可在沒有任何可見項目時直接顯示管理入口。
- 第一層顯示：角色、勢力、物品、能力、標籤。勢力是單一設定入口，不再分組織／陣營子類別。
- 管理流程：開啟管理面板 → 查看「目前顯示」與「可新增」 → 移除、加入或排序 → 關閉面板後立即更新側邊欄。
- 畫面狀態：一般、空白、已隱藏、可新增、恢復預設、尚無勢力、勢力尚無上層／下層。

## 已決定事項與理由

- 設定顯示配置應以「每本書」為單位；不同作品需要的設定類型不同。
- 「預設顯示」只代表新書的初始值，不代表永遠不可移除。
- 隱藏是導航層行為，不是資料生命週期行為。
- V5 第一版範圍收斂為：可配置設定集、單一勢力系統、標籤配置，以及地點／世界條目的基礎設定。
- 地圖、宗教、經濟、語言、科技樹、種族／血統完整系統與泛用其他設定模型不納入 V5。
- 第一版以單一「勢力」模型取代「陣營」與既有「組織」兩套模型；勢力本身不先固定政治、宗教或其他分類。
- 「層級」是每本書自訂名稱與高低順序的具體資料，只用來判定上下隸屬方向，不是規模、權力或重要性評分。
- 每個勢力先指定一個具體層級，才可建立上／下級關係。
- 一個勢力可以有多個上層與下層；所有隸屬都保存為直接連線，不從上層的上層推導額外隸屬。
- 允許跨級直接隸屬；只要求下級勢力的層級低於上級，不要求兩者層級相鄰。
- 修改勢力層級若會使既有隸屬失效，必須阻止修改，不可自動刪除或改寫關係。
- 隸屬關係只能由下級指向上級；不符合上下級語意的連線不成立，因此不把循環列為有效狀態。
- 聯盟先視為一個上層勢力節點，多個國家或其他勢力直接隸屬於它，不先建立獨立的同盟關係型別。
- 既有 `Organization`、角色—組織關聯與組織身分歷史不遷移為勢力；V5 實作時完整清除舊模型資料與關聯，保留角色、正文及共用 Node。
- 本工作版本為 V5。
- V5 第一版完全不建立勢力與角色、物品、能力、地點、事件或正文的連結。
- V5 第一版不保存勢力改變上層的歷史，只保存目前的直接隸屬結構。

### 本輪層級增補

- Schema：保留 `V5SettingsSchemaV1` 舊快照；V2 新增 `PowerLevel` 與可選 `levelID`，V3 補回完整勢力文字欄位與兩個預設層級。V1 勢力可先安全遷移成「尚未指定層級」，主資料 store 與 `NovelWriterSchemaV5` 完全不變。
- 舊勢力相容：V1 的 `PowerUnit` 保留原 UUID、名稱與簡介；因舊 `PowerSubordination` 沒有層級可驗證，升級後只清除這些舊勢力連線，且清理必須冪等。`BookSidebarSetting`、`Place`、`WorldTerm` 及其他五個 store 均不刪除、不改寫。
- 初始狀態：每本書預設兩層，以中性的「層級 1／層級 2」由高至低建立，避免寫死聯盟／國家等世界觀；作者可改名、排序或新增。同一本書層級名稱不可空白或重複。
- 寫入規則：關係服務同時驗證同一本書、雙方都有層級、下級 `sortOrder` 大於上級、關係不重複；允許跨越任意層級。嚴格的層級方向本身保證不會循環，不另建立可由使用者操作的循環規則。
- 勢力層級變更：UI 使用尚未保存的選擇值，先檢查該勢力全部上／下級；任何一條失效就回傳衝突清單並保持原層級與全部連線，全部有效才一次保存。
- 層級排序：拖曳先形成草稿順序，驗證全書所有連線後才整批保存；失敗時回復原順序。重新命名不影響關係；刪除已使用層級時阻止，未使用層級才可刪除。
- UI：勢力列表加入層級名稱與「管理層級」入口；勢力詳情保留簡介、高層管理員、其他名單、勢力關係、政治、宗教，並加入單選層級。未指定時停用關係新增並提示；指定後，上級／下級選單依高低方向過濾，但不限制相鄰層級。
- 錯誤處理：資料完整性操作改用明確成功／失敗結果，不以靜默 `guard` 假裝成功；持久化失敗沿用 settings store 的錯誤顯示，層級衝突使用作者可理解的勢力名稱與關係方向提示。
- 測試：新增 V1 檔案型 store → V2 遷移測試，逐一驗證勢力 UUID／文字及非勢力設定保留、只清除舊連線；涵蓋每書隔離、層級排序、空白／重名、跨級、多上／下級、同級／反向拒絕、勢力改層阻止、排序原子回復、已使用層級刪除阻止及重啟結果。
- 回歸：重跑 V5 專項與完整 XCTest、Debug build、無簽章 Release build、`git diff --check`，最後用隔離書籍驗收「建層級 → 建勢力 → 跨級直屬 → 衝突變更被阻止」。不使用正式作者資料做破壞性測試。

## 目標

讓人物、關係、能力、外觀、心理、物品等既有「時間序」資料，依作者提供的定位自然出現在正確的規劃視圖，不必再手動建立重複事件。

## 已確認需求

- 時間序資料若有時間戳記，顯示於世界時間軸，並依時間戳記排序／定位。
- 時間序資料若有具體正文位置，顯示於敘事大綱，並依所屬節次定位。
- 具體正文位置不是必填；沒有具體位置時，不建立也不保留敘事大綱投影，原始時間序資料仍存在。
- 同一筆資料若同時有時間戳記與具體正文位置，必須同時出現在兩個視圖。
- 產品流程保證至少提供其中一種定位；本工作不處理兩者皆無。
- 人物等原始時間序資料是唯一內容來源；世界時間軸與敘事大綱只建立投影／穩定關聯，不產生可各自編輯而分歧的 Event 或 OutlineItem 內容副本。
- 原始資料的內容或定位改變時，兩個視圖必須自動反映同一結果。
- 時間序資料設定具體正文位置時，作者同時選擇故事線；系統不自動猜測故事線。
- 選擇主線時可再選擇階段；未選階段則歸入「未分階段」。節次決定敘事畫布的橫向位置，故事線／階段決定所屬泳道。
- 第一版涵蓋目前所有有時間序／時間定位的來源：組織加入與身分歷史、能力時間序、外觀、心理、人物持有物品歷史、物品／物品副本歷史及一般人物關係歷史。
- 投影卡片顯示來源類型、人物／相關對象名稱與原始內容摘要；內容只能回原設定編輯，投影本身不可改出另一份內容。
- 敘事大綱投影只定位到節次，不建立節內文字錨點或 offset；沒有有效節次就不顯示。
- 移除節次時，敘事投影立即消失，原始時間序及可能存在的世界時間投影保留；重新指定節次後再顯示。
- 移除世界日期時，世界時間投影立即消失，原始時間序及可能存在的敘事投影保留。
- 刪除原始時間序時，兩邊投影一併消失；修改來源內容或定位時直接重新投影。
- 現有 Node 的「顯示於時間軸」開關在本功能中作為整筆時間序的規劃投影總開關：關閉後不映射到世界時間軸或敘事大綱，即使日期與節次皆存在；原始時間序與定位資料仍保留。重新開啟後，再依當前日期／節次恢復對應投影。

## 現況與缺口

- 主資料中的多種人物／設定歷史以 `Node` 作為共用時間定位；`Node` 可同時帶世界日期與 `Section`。
- 世界時間軸目前主要顯示 `Event`；敘事大綱顯示獨立 StoryPlanning store 的 `OutlineItem`。
- `TimelineEventCardMetadata` 只負責 Event 與 OutlineItem 的選擇性連結，尚未讓人物等時間序資料依定位投影到兩個視圖。
- 若直接複製成 Event／OutlineItem，會產生同步、刪除與復原的一致性問題，資料語意需先確認。
- 現有 `CharacterNodePicker` 讓各來源選擇或建立共用 Node；Node 的世界日期與節次可分別留白，並另可顯示於時間軸。主 store 模型直接關聯 Node，AbilityProgress／ItemCopy 等獨立 store 則保存 `nodeID`。
- 同一 Node 可被多筆來源共用，因此故事線與階段歸屬必須屬於來源紀錄，不可存在 Node 上。
