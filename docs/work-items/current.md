## V4.4.2 需求（R，已確認）

### 現況與問題

- 書籍的實際正文資料結構是 `Volume（卷） → Section（節）`，但 V4.3.1／V4.4.1 的大綱畫面與規格曾誤稱為「幕／節次」，混淆了書籍結構中的卷與編輯器內的「幕標題」。
- 目前橫向敘事大綱只投影到節次欄位，尚未呈現節內既有的幕標題層級。

### V4.4.2 實作與測試計畫（I，已確認）

1. 建立純資料的正文結構解析器，從每一節的 `AttributedString` 讀取既有幕標題與其字元範圍。幕標題判定共用編輯器既有規則，避免匯出、編輯器與大綱各自判斷。

### 提案規則

1. 每個主線階段均有明確的開始定位，統一參照既有書籍結構的兩層位置「幕／節次」，不再由某筆項目反推。有效來源顯示目前名稱；原定位的幕或節被刪除時，保留最後可讀的名稱與識別，顯示「來源已刪除」，不得自動改指向其他位置。
2. 「已完成」是正文來源的事實標記：只有從正文選取文字建立的項目可取得；手動新增項目只可為背景、草稿或預定。既有手動「已發生」資料必須保留，並以「需要補正文來源或調整狀態」提示作者，不能靜默改寫。
3. 手動項目以「安置位置」取代排序數字：建立後先顯示在所屬階段的「待安置」區；作者可選擇放在幕首、幕末，或接在該幕某一筆項目之後。同一掛點的多筆手動項目可用清楚的上／下移動調整先後，不使用裸露的數字排序。
4. 排序規則以作者可預測的方式組合：階段先依其開始的幕／節次排序；正文項目依正文位置排序；手動項目依其安置位置插入，沒有安置時固定留在「待安置」區。安置目標被刪除時，項目回到待安置並顯示原因，不隨意改放他處。
5. 使用清楚的提示區分「正文定位」、「尚未寫入正文」、「來源已刪除」、「待安置」與「需要調整狀態」；每一種提示都提供下一個可做操作。
6. 大綱介面以可掃讀的階段卡片為主：標題列顯示階段名稱與開始定位；項目預設只顯示標題、事實／規劃狀態與來源／安置資訊，點選才展開內容與次要操作。階段／項目的危險刪除仍保留明確確認。

- 每張階段卡標題列分兩行：第一行是收合、階段名稱與更多操作；第二行是「開始於　幕名 · 第 N 節｜節次名稱」。來源已刪除時改為「原定位　…（來源已刪除）」，以醒目但非破壞性警示呈現。

- 項目預設為一行摘要：狀態圓點、標題、第二行的正文來源或安置資訊，及右側小型狀態標籤。作者可掃讀而不需展開全部內容。

#### 手動項目的安置

- 每張階段卡內保留「＋ 新增規劃項目」，新增後直接展開為手動項目，初始狀態為草稿、位置為「待安置」。

- 沒有階段時，顯示單一「建立第一幕」按鈕與「請先選擇開始幕與節次」說明。
- 有階段但沒有項目時，展開後只顯示「尚未安排項目」與新增規劃項目。
- 原定位被刪除的階段及舊手動已完成項目不阻礙閱讀或寫作；只在對應卡片顯示可行的修正操作。

## 需求提案（R）

### 1. 故事背景的選填引導

- 保留既有自由長文字區，作為作者可任意記錄的「其他背景」；不要求填寫任何建議欄位。
- 在其上方加入一組可留白的建議區域，候選項目為：世界／時代背景、故事前提、主要衝突、主角目標、核心主題。
- 建議欄位僅協助作者思考，不自動產生、不限制字數、不影響大綱項目或匯出。

### 2. 大綱排序以文本位置優先

- 具 `OutlineItemAnchor` 的項目，優先依正文書籍結構中的卷／節順序，再依該節內錨點位置排序。
- 沒有正文來源的手動項目仍可保留，並排在同一故事線（或階段）中具正文來源項目之後；彼此依既有手動 `sortOrder`、建立時間與 UUID 穩定排序。
- 若錨點指向已不存在的節，不刪除資料；視為無法定位的項目，排在有可用正文位置的項目之後。
- 此提案以「文本內位置」解讀為目前書籍的卷／節顯示順序加上節內 offset；不依文字內容匹配後的動態位置改寫資料。
- 項目編輯列不提供手動輸入排序值；改為唯讀分別顯示正文來源的「卷」與「節」。沒有可用來源、來源已失效或任一名稱未填時，該欄顯示「從缺」。既有 `sortOrder` 不清除，暫作穩定後備排序，待後續另行設計手動排序操作。

### 3. 階段改為獨立欄位

- 僅主線使用階段欄位。每一個既有階段都各自顯示為一個內容區塊，項目直接建立於該階段內，不再於每筆項目的公共編輯區以下拉選單選取階段。
- 手動新增主線項目時，若已有階段，一律歸入排序最後的階段；作者可在項目編輯時移至另一階段。從正文加入主線項目時，每個階段以其中最早的正文來源位置為開始標記，新項目歸入最近且不晚於其文本位置的階段；在所有開始標記之前則歸入第一階段，沒有可用開始標記時才歸入最後階段。
- 未建立任何階段的主線維持一個「未分階段」欄位，不阻礙既有資料；非主線故事線維持單一內容欄位。
- 既有 `stageID == nil` 的主線項目保留在「未分階段」欄位，不會在遷移時自動改寫到最後一個階段。

## 初步驗收條件

- [ ] 故事背景提供已確認的一組選填引導欄位，所有欄位留白時仍可只使用自由文字區。
- [ ] 具有效正文來源的大綱，依卷／節與節內文字位置先後排列；手動項目與無效來源資料仍可見且排序穩定。
- [ ] 主線每個階段各自呈現一個內容欄位，使用者不必在共用區域為每項選擇階段。
- [ ] 建立主線項目時，未指定階段會預設進入最後一個階段；無階段時保留未分階段欄位。
- [ ] 既有 V4.2.1 資料、正文、來源錨點、故事線與手動項目均不遺失或被不預期改寫。

## 需求確認紀錄

- 使用者確認故事背景先採五個建議欄位。
- 使用者確認「有正文來源的項目依卷／節與節內位置排列；無來源或失效來源保留、排後並維持手動順序」。故事線與階段是獨立欄位，因此排序只在各自欄位內比較，不跨欄位混排。
- 使用者確認需提供項目移至另一主線階段的操作。

## UI 提案（U）

### 故事背景

- 依序顯示五個可折疊、可留白的文字欄位：世界／時代背景、故事前提、主要衝突、主角目標、核心主題。
- 下方保留較大的「其他背景」自由文字區，承接原有內容；既有 `backgroundText` 顯示在此區，不遺失內容。
- 各欄位維持既有儲存按鈕與錯誤提示；全部留白時不顯示錯誤。

### 敘事大綱

- 主線顯示為一串垂直欄位：先是「未分階段」（只在含既有未分階段項目或尚無階段時顯示），再依階段排序逐一顯示「階段名稱」與該階段項目。「未分階段」與每個階段皆預設收起，作者點擊標題列後才展開內容。
- 每一階段標題列提供「＋ 新增項目」；在主線工具列新增的項目直接進入最後一個階段。非主線故事線維持既有單一內容欄位。
- 各欄位內以正文位置排序；手動／失效來源項目置於該欄位最下方並穩定排列。
- 每筆主線項目編輯列的狀態旁加入「移至階段」選單；目前階段顯示為選取值，選擇「未分階段」可移出階段。
- 每筆項目編輯列在狀態旁唯讀分別顯示「卷」與「節」來源；不顯示或允許編輯排序數字。
- 每個階段標題列保留垃圾桶刪除按鈕，點擊後顯示確認對話框。刪除階段會一併刪除其中項目與正文來源標記，不跳轉至未分階段；正文內容不連帶刪除。

### 時間軸

- 維持故事線分欄；主線欄內依階段加上小標題分區，不增加第二套項目編輯或排序規則。
- 所有項目仍是同一筆 `OutlineItem`，從敘事大綱或時間軸編輯後同步反映。

### 空白與例外狀態

- 主線沒有階段：僅顯示預設收起的「未分階段」；展開後顯示新增項目按鈕。
- 已有階段但沒有項目：階段預設收起；展開後顯示空白提示與新增按鈕。
- 主線沒有項目但有階段：工具列新增項目直接進入最後一個階段。
- 無正文來源、失效來源、或手動建立項目：不顯示錯誤，置於所屬欄位最下方。

## 實作與測試計畫（I）

### 資料與遷移

1. 使用既有 `BookPlanningProfile.backgroundText` 保存可版本化 `StoryBackgroundContent`：世界／時代背景、故事前提、主要衝突、主角目標、核心主題與其他背景。非結構化舊值一律讀為其他背景。
2. 不新增 SwiftData schema 或資料遷移，避免現有 VersionedSchema 快照因重複模型型別而無法安全區分。首次儲存背景時才將既有自由文字包裝為結構值，內容不遺失。
3. `StoryPlanningStore` 新增 `moveOutlineItem(_:to:)`（只允許同一主線的階段或 `nil`）與 `deleteStage(_:)`。後者在單一 save 刪除所屬項目及其 anchor 後才刪階段；失敗 rollback、reload，且不修改正文或其他故事線。
4. 新增正文優先排序入口：接收 `BookStructure.orderedSections(in:)` 的節順序與內容快照；有有效 anchor 的項目以卷／節順序與 `anchor.resolvedOffset(in:)` 排列；無 anchor、失效節或無法定位者置後，再以 `sortOrder`、建立時間、UUID 穩定排序。

### 介面

1. `BookBackgroundView` 改為五個可留白的多行文字欄位，底部保留既有大型 `backgroundText` 區並標為「其他背景」；沿用明確儲存與錯誤提示。
2. 主線內容改為可收合的「未分階段」與 `StageSectionView`，初始均收起；展開後才顯示項目與新增按鈕。主線沒有階段時仍顯示未分階段欄位。
3. 從主線工具列新增、或正文右鍵建立主線／主線草稿時，預設指定排序最後的階段；由階段欄位新增則指定該階段。非主線不變。
4. 移除公共項目編輯列的階段 Picker，改為主線項目的「移至階段」選單；非主線不顯示。移動一律透過 store 操作並回報錯誤。
5. 移除項目編輯列的手動排序輸入，改以其 anchor 解析目前書籍的「卷」與「節」為唯讀來源資訊；缺少可用 anchor、卷、節或名稱時，缺少的欄位顯示「從缺」，既有 `sortOrder` 僅留作不顯示的穩定後備排序。
6. 階段標題列加入垃圾桶與 confirmation dialog，明示會一併刪除該階段的項目與正文標記、保留正文；時間軸重用相同收合／分區與排序資料，不建立第二套狀態。

### 文件

1. 更新故事規劃規格與 V4.3 工作範圍，清楚區分產品版本與資料 schema。
2. 更新 `data-model.md`、`backup-and-migration.md`、`consistency-audit.md`，記錄相容背景保存、項目移動、階段刪除的 nullify 規則及正文優先排序。
3. 完成時更新 `project-status.md`、驗收條件、交接與測試證據；未完成前不標為已發布。

### 測試與驗證

1. 背景：五個欄位與原自由文字保存、非結構化舊文字讀取、重開與原文字保留。
2. 排序：跨卷／節、同節不同 offset、正文前插後重新解析、手動項目、失效節來源、同值後備排序。
3. 階段：新建主線及正文建立項目預設最後階段；移至其他／未分階段；刪除空階段與含多項目／anchor 階段後資料保留；失敗 rollback。
4. UI 冒煙：背景全空與僅填自由區、收合／展開、最後階段預設、新增／移動／刪除確認與取消、時間軸同步、正文回跳。
5. 回歸：完整 macOS 測試、Debug 與無簽章 Release build、`git diff --check`；人工 UI 冒煙依本機環境記錄結果。

### 風險與回復

- 背景引導不升級 schema；舊自由文字僅在使用者儲存時轉為結構值，且完整保留在其他背景。
- 故事規劃 store 不直接讀主 store；排序只接收唯讀節順序與內容快照，不建立跨 store relationship 或交易。
- 正文重複文字會使最近位置推定有歧義；沿用既有最接近原 offset 規則，失效時保留項目並置後。
- 不移除 `sortOrder`，讓手動或失效來源資料仍有可預測順序。
